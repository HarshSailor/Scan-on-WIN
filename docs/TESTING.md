# Проверка Scan on WIN

Приложение собрано и проверено на Windows x64. Результаты автоматических тестов находятся в `artifacts/test-results/results.json`, оконных тестов — в `artifacts/ui-tests/result.txt`. Снимки WPF создаются тестовым проектом из собственного визуального дерева с синтетическим документом.

## Доработки 1.0.1

18 октября 2026 года пройдены 18 проверок Core, включая реальные PDF/PNG/JPG после переключения формата, замену расширений, многостраничный PDF и существующий OCR. Оконный набор открывает настоящий выпадающий список и выбирает PNG/JPG/PDF через WPF AutomationPeer, сохраняет двухстраничный документ в каждом формате и проверяет запоминание выбора.

Печать проверена программно: разбор диапазонов, консервативное сопоставление устройств (включая неоднозначность и конфликты IP/серийного номера), отслеживание источника документа, пропорции/поля и создание двухстраничного XPS из выбранных страниц. Это настоящий вывод через XPS-сериализатор, без физического задания принтеру.

Дополнительно `--installed-printers` прочитал реальные очереди Windows и возможности **Samsung SCX-4200 Series (USB001)**, проверил автоматическое предложение этой очереди и предпросмотр всех/текущей/страниц `1,3`. Отчёт и снимки: `artifacts/ui-tests/installed-printers/`. Физическая печать не выполнялась; стандартный Windows PrintDialog подключён в коде, его подтверждение и отправка задания в этой проверке не выполнялись.

Окно пожертвования, кнопки «Пожертвовать»/«Закрыть», точный URL, `UseShellExecute` и обработка ошибки запуска проверены с подставленным обработчиком браузера. Отдельный запуск настоящего Windows HTTPS-обработчика открыл Chrome с заголовком «Переход в сбор». Средство Computer Use остановило дальнейшую проверку, поскольку не смогло надёжно определить URL браузера; загрузка содержимого страницы и платёжные действия не проверялись.

Оконные проверки с реальными очередями запускаются отдельно:

```powershell
dotnet run --project tests/ScanOnWin.UiTests -- artifacts/ui-tests --installed-printers
```

Параметр `--open-donation` дополнительно открывает заданную ссылку в браузере; обычный тестовый запуск браузер не открывает. Хеши исходников сканеров, OCR, обработки изображений и хранения документа сверены с состоянием до доработок.

## Реальный аппаратный тест

18 октября 2026 года после подтверждения готовности тестового листа выполнено настоящее сканирование **Samsung SCX-4200 Series через WIA**: стекло, 300 DPI, цвет, одна страница 2480×3507 px. Успешно созданы PNG, JPG, PDF, TXT и PDF с OCR. Отчёт: `artifacts/hardware-test/20261018-000258/hardware-result.json`; документы: папка `output` рядом. Содержимое скана не включается в исходный архив и установщик.

Это проверка одного устройства и одного режима. ADF, duplex, реальное сканирование через TWAIN и AirScan, другие модели по-прежнему требуют отдельной проверки.

## Автоматические проверки

`tests/ScanOnWin.Tests` — исполняемый тестовый набор с ненулевым кодом выхода при любом сбое. Он проверяет реальные службы хранения/обработки/экспорта/OCR, а получение изображений заменяет явно обозначенный **MockScanner**, присутствующий только в тестовом проекте.

- Одна страница, несколько страниц, ADF/duplex-параметры MockScanner.
- Отмена после завершённой страницы; отсутствие новых результатов после отмены.
- Ошибка недоступного устройства и неподдерживаемого DPI; сохранность предыдущих страниц.
- Восстановление манифеста, поворот, обрезка, яркость/контраст, отмена и перестановка страниц.
- Отказ редактирования с сохранением исходной страницы.
- Настоящие PNG/JPG с нумерацией; размеры и контроль пикселей PNG.
- Конфликт существующих файлов и отмена экспорта.
- Настоящий одностраничный/многостраничный PDF; число страниц, физические размеры, наличие исходных изображений.
- Настоящий Tesseract OCR: eng, rus, rus+eng; TXT из нескольких страниц.
- PDF с невидимым OCR-слоем: извлечение латиницы/кириллицы через независимую библиотеку PdfPig, координаты символов и наличие изображения на каждой странице.
- Сжатие PDF, отсутствующие языковые модели, повреждённые настройки, некорректные имена, отсутствие содержимого документа в журнале.

`tests/ScanOnWin.UiTests` — запуск настоящего WPF-окна в изолированном профиле: восстановление и отображение страницы, блокировка сканирования без устройства, работа сохранения, команды поворота и отмены, светлая/тёмная темы, окно 1020×680, пустой документ. Эти тесты не обращаются к физическому сканеру и не добавляют имитируемое устройство в приложение.

Дополнительное обнаружение через реальные API:

```powershell
dotnet run --project tests/ScanOnWin.Tests -- artifacts/test-results --discover --native-worker artifacts/portable/ScanOnWIN.exe
```

Проверяется факт вызова WIA/TWAIN/eSCL, а пустой список является допустимым результатом. Ошибки отдельных интерфейсов сохраняются отдельно и не считаются доказательством работоспособности оборудования. В ограниченной среде доступ к WIA может быть запрещён; с обычным доступом обнаружен драйвер Samsung SCX-4200 и выполнен описанный выше тест.

## Что не проверено на физическом оборудовании

Сетевое получение страниц, фактическая подача/окончание бумаги ADF, duplex и порядок сторон, реальные замятия, занятость устройства, аппаратная отмена, остальные модели, сканирование через TWAIN обеих разрядностей. Наличие реализации не заменяет такую проверку.

## Проверка перед распространением

На чистых Windows 10 и 11 x64 установить EXE, проверить ярлыки, запуск без отдельно установленного .NET, OCR без интернета и удаление через настройки Windows. Затем повторить на доступных реальных сканерах: WIA, TWAIN 32-bit/legacy/64-bit, AirScan; стекло, ADF, duplex; допустимые и недопустимые DPI/размеры/цвет; отмена, пустой ADF, замятие, отключение питания, занятость драйвера. Сверить PDF с изображением после обрезки/поворота; проверить выделение текста в обычном PDF-просмотрщике.

Также вручную проверить: недоступную папку, полный диск, очень длинный документ, несколько мониторов и масштабы Windows 100/150/200%. Текущий набор имитирует часть отказов и проверяет сохранность, но не заполняет физический диск и не меняет системные ACL.

Установщик должен успешно компилироваться в `dist/ScanOnWIN_Setup.exe`. Наличие EXE подтверждает сборку, но не означает прохождение всех перечисленных аппаратных испытаний. Authenticode-подпись издателя и публичная публикация в этот проект не входят.
